# Процесс проектирования и нормализации базы данных

## 1. Исходная (денормализованная) структура

`Habits_Flat (habit_id, title, user_id, username, category_name, label_names)`

**Проблемы исходной структуры:**
- **Избыточность:** username дублируется для каждой привычки пользователя
- **Аномалия обновления:** при изменении имени пользователя нужно обновлять много строк
- **Аномалия удаления:** удаление последней привычки может привести к потере данных о пользователе
- Нарушение 1NF при хранении нескольких категорий/меток через запятую

## 2. Нормализация до 1NF (Первая нормальная форма)

**Цель:** Все атрибуты атомарны, нет повторяющихся групп.

- Вынесли категории и метки в отдельные таблицы `Categories` и `Labels`.
- Связи реализуются через промежуточные таблицы.

## 3. Нормализация до 2NF (Вторая нормальная форма)

**Цель:** Устранить частичные зависимости.

- Данные пользователя вынесены в отдельную таблицу `Users`.
- В таблице `Habits` остался только внешний ключ `user_id`.

## 4. Нормализация до 3NF (Третья нормальная форма)

**Цель:** Устранить транзитивные зависимости.

- Описательные поля категорий и меток хранятся только в своих таблицах.
- В `Habits` нет полей `category_name` или `label_name`.

## 5. Реализация связей «Многие-ко-многим» (M:N)

- `Habit_Categories (habit_id, category_id)` — составной первичный ключ
- `Habit_Labels (habit_id, label_id)` — составной первичный ключ

## 6. Финальная схема

- Users (user_id PK, username, email, created_at)
- Categories (category_id PK, name, description)
- Labels (label_id PK, name, color)
- Habits (habit_id PK, title, description, due_date, priority, status, created_at, updated_at, user_id FK)
- Habit_Categories (habit_id FK, category_id FK)
- Habit_Labels (habit_id FK, label_id FK)
